## 2. Платформа: HTML-виджеты Telegram (Bot API 10.4, вышел 2026-11-09)

### Источники
- Официальная спецификация — репозиторий **TelegramMessenger/widget-sandbox**. В этой среде `github.com` не открывается через WebFetch и не отвечает в `gh api`, но **`git clone` работает**:
  `git clone --depth 1 https://github.com/TelegramMessenger/widget-sandbox.git /tmp/ws`
  Главное в нём:
  - `docs/sdk-v1.md` — JS API виджета (`window.TelegramWidget`);
  - `docs/profile-v1.md` — что разрешено (HTML, CSS, canvas, JS);
  - `docs/tgw-format.md` — формат на сервере и связка с Bot API;
  - `packages/core/profile.json` → `tables.uaStylesheet` — стандартная таблица стилей Telegram, ею пользуется тест `tests/test_telegram_ua_css.py`.
- **aiogram с Bot API 10.4** пока только в PR #2004 (версия 3.32.0, `__api_version__ = "10.4"`, автор — мейнтейнер JRoot Junior). Все тесты ветки проходят (2598 passed).
  `pip install "git+https://github.com/aiogram/aiogram@refs/pull/2004/head"`
  Есть `bot.send_widget(chat_id, html, width, height, public_data, chat_data, caption, allow_queries, is_shared, reply_markup, …)`, `send_shared_widget`, `answer_widget_query`, `edit_message_widget_data`, `edit_shared_widget_data`, роутеры `router.widget_query()` / `router.shared_widget_query()`, шорткат `query.answer(data=...)`. `WidgetQuery` содержит `id, from_user, chat_instance, type, data, chat, message_id, inline_message_id, chat_type, widget_id`, но **не** `chat_data`.
- Пакет `aiogram-widgets` на PyPI к этому **не относится**: это старая библиотека пагинации 2023 года.

### Жёсткие лимиты
| Что | Лимит |
|---|---|
| HTML виджета | 1–32768 байт и **≤ 4096 байт после zlib level 9** (главный лимит) |
| `public_data`, `chat_data` | ≤ 1024 байт каждое (UTF-8) |
| Ответ бота (`answerWidgetQuery`) | ≤ 1024 байт, бот обязан ответить за 15 с |
| `request(data)` | данные 1–64 байта; один запрос в полёте; один на нажатие; фоновые — только в личке: один при появлении на экране, дальше не чаще раза в 5 с |
| Запросы пользователя | ≤ 5 запросов за 5 с со всех виджетов бота |
| Canvas | **4000 команд на один canvas за одну задачу** (дальше `RangeError`); все canvas вместе ≤ 2048² пикселей |
| CPU | > 500 мс непрерывного JS в одной задаче → виджет убивают, на экране остаётся последний кадр |
| Память | 8 МБ |
| Запросы раскладки | ≤ 128 синхронных (`getBoundingClientRect` и т.п.) за задачу |
| «Тяжёлые» элементы | ≤ 16 одновременно (тени с размытием, фильтры, opacity < 1), из них ≤ 2 с backdrop-filter |
| Размер пузыря | ширина от 200 до ширины пузыря, высота 50–600 (параметры `width`/`height` в `send_widget`) |
| `localStorage` | 4 КБ на сообщение, на устройстве; на бота не уходит |
| Таймеры, когда виджет скрыт | не чаще раза в секунду, `requestAnimationFrame` не вызывается |

### Что разрешено и что нет (profile v1)
- **Разрешено:** свой JS в `<script>` (QuickJS: ES2023, Promises, таймеры, `requestAnimationFrame`, **`eval`/`new Function`**), canvas 2D (пути, градиенты, `drawImage` из другого canvas, в том числе невставленного в DOM, текст, `globalAlpha`, `imageSmoothingEnabled`), inline SVG (без clipPath/mask/SMIL), 2D-трансформации CSS, CSS-анимации и переходы, `<button>` (по умолчанию в стиле клиента), CSS-переменные темы `--tg-theme-*`, `env(safe-area-inset-bottom)`.
- **Запрещено или не работает:** `<input>`, `select`, `textarea`, `form`, `label` (валидатор их вырезает, на этом сломалась первая версия), сеть (`fetch`/XHR/WebSocket), внешние скрипты и стили, `import()`, **`getImageData`/`putImageData`** (ничего не рисуют), `createPattern`, `globalCompositeOperation`, `shadowBlur`, `ctx.filter`, 3D-трансформации, клавиатура, `alert`.
- **Стандартная таблица стилей Telegram** меняет внешний вид. У `table` поля 0.6em, у ячеек отступы 0.3×0.6em и **линия 1px снизу** (цвет `--tg-theme-section-separator-color`). Отступ `body` — `--tg-text-padding`. Обнулять явно.
- **Жесты:** нажатие и удержание — виджету. **Вертикальное протягивание всегда забирает прокрутка чата** (виджет получает `pointercancel`), и обойти это нельзя. Горизонтальное протягивание и удержание забирает виджет на элементах с `touch-action:none`. Если палец сначала пошёл вбок, протягивание остаётся за виджетом по обеим осям. Первые 20 px от левого края резерв под системный жест «назад».
- **Время сообщения** рисуется поверх нижнего угла виджета, если нет подписи → `padding-bottom: env(safe-area-inset-bottom)`.
- **Продакшен сейчас:** виджеты только в личке с ботом, у них автоматически protected content (**не пересылаются**), в inline-режиме нельзя. Клиенты ниже layer 233 показывают «неподдерживаемое сообщение».
- **`public_data`** хранится в сообщении и доступен синхронно с первой строки скрипта. По нажатиям **никуда не передаётся**, меняется только через `editMessageWidgetData` (тогда приходит событие `publicDataChanged`). Опрос раз в 30 с бывает только у shared-виджетов с `watchPublicData()`.
- **`allow_queries=True`** обязателен, чтобы работал `TelegramWidget.request()`. Клиент помечает такой виджет как «может отправлять данные боту».
- `request()` возвращает `Promise<{result}>` или отклоняется с `error.code`: `NOT_ALLOWED | BUSY | RATE_LIMITED | TIMEOUT | FAILED | INVALID_ANSWER`.

## 4. Как устроена игра (`src/doom.html`)

- **Экран:** canvas 320×200, растянут на 100% ширины, `imageSmoothingEnabled=false` (пиксельная картинка). Под ним `<table id="k">` — 7 кнопок, `data-k`: `f` ▲, `b` ▼, `L` ◀, `R` ▶, `l` ⟲, `r` ⟳, `s` FIRE. Пустые ячейки — `td.e`.
- **Рейкастер:** 160 столбцов по 2 px, DDA в стиле Lode. Каждый столбец стены — одна команда `drawImage(T, …)` с полоской текстуры плюс `fillRect` с чёрной прозрачностью (туман по расстоянию и затемнение боковых граней). Буфер глубины — `Z[x]`.
- **Текстуры** (canvas `T` 256×64): 0 кирпич (основа и швы), 1 техно (основа и световая полоса), 2 камень, 3 зелёная дверь выхода. Генерируются функцией `load()` из цветов пакета: шум блоками 4×4 через `noise()`. Около 2140 команд, это отдельный canvas, лимит 4000.
- **Спрайты** (canvas `SP` 512×64, кадры по 64 px). Индекс кадра = `e.t` или состояние монстра:
  `0` монстр · `1` монстр раненый (буквы b/c перекрашиваются в `#f84`/`#fc8`) · `2` лужа крови / мёртвый · `3` аптечка · `4` патроны · `5` бочка · `6` факел · `7` колонна.
  Пиксель-арт 16×16 хранится левой половиной (8×16), `pix()` отражает и рисует отрезками одного цвета.
- **Сущности** `en[]`: `{x,y,t,h,cd,fr,a}`; `t`: 0 монстр, 2 кровь, 3 аптечка, 4 патроны, 5 бочка (твёрдая), 6 факел (проходимый, висит на стене), 7 колонна (твёрдая), 9 подобрано. Столкновения — `bl(x,y)`: стены, плюс бочки и колонны в квадрате ±0.3.
- **Состояние `st`:** 0 заставка, 1 игра, 2 смерть, 3 загрузка уровня. FIRE на заставке или после смерти → `start()`; во время загрузки игнорируется.
- **Генерация уровня `gen()`:**
  1. Размер `S = min(11+2·lv, 25)`.
  2. Лабиринт DFS по нечётным клеткам, плюс 10% стен убирается ради петель.
  3. Залы 3×3: `2+lv/2` штук, центр на чётных координатах ≥ 4, чтобы колонна не встала на старт.
  4. BFS от старта (1,1); дальняя клетка `f` → соседняя стена становится дверью (значение 4).
  5. Монстров `tot = 3+2·lv`, плюс 2 аптечки и 2 ящика патронов, все не ближе 4 шагов к старту.
  6. Декор: колонны в 4 углах каждого зала (сдвиг 0.35 к углу); бочки в тупиках (3 стены, 60%, кроме `f` и старта); факелы у стены (15% клеток со стеной, сдвиг 0.42).
- **ИИ:** монстр спит, пока игрок его не увидит (`e.a`: выставляется при отрисовке, если спрайт виден ближе 9 клеток), потом идёт к игроку. Вплотную (<0.8) бьёт раз в 0.9 с.
- **Характеристики из пакета `ST=[hp, speed, dmg]`:** ХП = `ST[0] + lv/3`, скорость = `ST[1] + 0.05·lv`, урон = `ST[2] + rnd·6`.
- **Стрельба:** хитскан по центральному столбцу, ближайший живой монстр с `|sx−80| < w/4` и `ty < Z[80]`. Перезарядка 0.3 с, при удержании автоогонь.
- **Управление** (самое дорогое по байтам): на `pointerdown` меряем прямоугольники кнопок (7 запросов раскладки), `P[pointerId]` = кнопка под пальцем, на `pointermove` пересчитываем, `pointerup`/`pointercancel` → удаляем; `k` = объединение нажатых. Обработчики move/up висят на `document`.
- **Переход уровня:** вход в дверь → `lv++`, +25 ХП, `st=3` → `TelegramWidget.request('lv:'+lv)` (фоновый, без нажатия: разрешён только в личке) → `load(result)` → `gen()`. При ошибке или без ответа — `gen()` со старой темой.
- **`load(pack)`** разбирает `palette|monster|barrel|torch|column|medkit|ammo|colours|stats|name`. При старте и рестарте берётся `TelegramWidget.publicData`. Если данных нет — защита `d&&` в `pix()`: раньше был **бесконечный цикл**, и Telegram убил бы виджет по CPU.

## 8. Риски и открытые вопросы

- Не проверено на устройстве: протягивание, начатое строго вертикально (⟳ → FIRE вниз), по правилам заберёт прокрутка чата. Если пользователь пожалуется — поставить FIRE в один ряд с поворотами.
- Мультитач в виджетах в документации прямо не описан. Логика поддерживает несколько `pointerId`, но на устройстве не проверялась.
- Темы уровней через `request` в живом Telegram не проверялись: нужен бот с `allow_queries=True` и обработчиком `widget_query`. В группах фоновые запросы запрещены → там темы не сменятся (игра продолжит со старой).
- Запас по размеру ≈150 байт: каждая новая фишка требует что-то вынести или урезать.
- Прогресс (уровень, рекорд) живёт только в памяти виджета: при пересоздании игра начинается сначала. Сохранить можно через `localStorage` (4 КБ на сообщение).

## 9. Идеи, которые предлагали пользователю (не сделаны)

Огненные шары у бесов; второй тип монстра на уровне; таблица лидеров и рекорды через `request` и `chat_data`; сохранение прогресса в `localStorage`; больше тем в `themes.py`; ежедневный челлендж с одинаковым сидом для всех.
